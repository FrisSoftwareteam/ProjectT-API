2. Global request and response rules

Headers

Accept: application/json
Authorization: Bearer <token>
Content-Type: application/json   // JSON mutations only

For report downloads, request a blob/binary response. For the original file upload, use browser FormData and allow the browser to create the multipart boundary.

Three response envelopes

KindShape
Single-record read{ "data": { ... } }
Mutation{ "success": true, "message": "...", "data": { ... } }
Paginated read{ "current_page": 1, "data": [], "last_page": 1, "per_page": 50, "total": 0, "meta": { ... } }
Quantity handling: share quantities are returned as decimal strings such as "248889.000000". Do not convert them to JavaScript floating-point numbers for equality or financial calculations. Display with the returned meta.unit_precision.

4. Screen 1 — Exception resolution workbench

List endpoint

GET /api/cscs/uploads/{batchId}/exceptions
  ?resolution_status=UNRESOLVED&search=C111111111&page=1&per_page=10

Both status and resolution_status are accepted. Search matches transaction, identifier, code, message or row number. Use meta.exception_counts for the Total, Blocking, Warning, Resolved and Remaining cards.

Detail panel behavior

  1. Store the clicked exception row as selectedException.
  2. Render severity, is_blocking, parsed_record, suggested_resolution, allowed_resolution_types, matched_account and resolution_history directly from that object.
  3. If the design needs both movement legs, call GET /transactions/{selectedException.tran_no}.
  4. After any resolution, clear the selection and refresh exceptions, batch, preview and transaction counts.

Confirm an existing account mapping

POST /api/cscs/uploads/{batchId}/exceptions/{exceptionId}/resolve

{
  "resolution_type": "MAP_ACCOUNT",
  "register_account_id": 445,
  "reason": "Confirmed against the shareholder register."
}
Required: register_account_id is the internal shareholder-register-account ID. Find it with GET /api/shareholders?register_id={registerId}&search={query}; search accepts names, shareholder numbers, CHNs and CSCS numbers.
Buttonresolution_typeAdditional rule
Confirm MappingMAP_ACCOUNTregister_account_id required; account must belong to the batch register.
Mark as ReplayCONFIRM_REPLAYA matching previously posted movement must exist.
Exclude RecordRULE_EXCLUDEDApplies a documented exclusion to the complete transaction group.
 
// Replay
{ "resolution_type": "CONFIRM_REPLAY",
  "reason": "Confirmed as an already posted CSCS movement." }

// Exclusion
{ "resolution_type": "RULE_EXCLUDED",
  "reason": "Excluded under the approved documented CSCS rule." }

Every resolution reason is required and must contain 10–1000 characters. A successful response states that revalidation is required.

Creating a new shareholder/account from the panel

POST /api/shareholders → receive shareholder.id → POST /api/shareholders/{shareholderId}/register-accounts → receive registerAccount.id → POST CSCS exception resolve with MAP_ACCOUNT + registerAccount.id → POST /api/cscs/uploads/{batchId}/reconcile
Do not stop after account creation. The CSCS exception is unresolved until the final MAP_ACCOUNT call succeeds.

Submission gate

Before enabling submission, confirm all of the following from the refreshed batch:

  • workflow_status === "RECONCILED";
  • summary.unresolved_exceptions === 0;
  • debit and credit totals match;
  • snapshot_hash is present; and
  • allowed_actions contains submit.

Authoritative button list

{
  "data": {
    "id": 101,
    "workflow_status": "DRAFT_REVIEW",
    "allowed_actions": ["view", "resolve", "revalidate", "cancel"]
  }
}

Always combine allowed_actions with the frontend permission model. Refresh it after every mutation because workflow state and actor separation can change what is legal.

Authorization request

POST /api/cscs/uploads/{batchId}/post
{ "comment": "Approved for controlled posting." }

A successful request returns HTTP 202 Accepted with status POSTING_QUEUED. The user’s acknowledgement checkbox and operational comment are frontend fields; submit the comment after the checkbox has been checked.

Segregation of duties: the maker can never post their own batch. The active policy may also require the poster to be different from the checker. A 403 response is final authorization feedback, not a condition to bypass or retry automatically.

9. Posting monitor and final verification

Poll posting status

GET /api/cscs/uploads/{batchId}/posting-status
const active = new Set(['POSTING_QUEUED', 'POSTING']);

async function pollPosting(batchId, signal) {
  while (!signal.aborted) {
    const { data: response } = await api.get(
      `/api/cscs/uploads/${batchId}/posting-status`, { signal }
    );
    const posting = response.data;
    if (!active.has(posting.status)) return posting;
    await new Promise(resolve => setTimeout(resolve, 3000));
  }
}
ResultFrontend action
POSTEDStop polling and load verification summary.
POSTING_FAILEDShow sanitized failure_reason. Offer retry only when allowed_actions permits posting.
STALEReturn the batch to the maker; holdings or snapshot changed and reconciliation/approval must repeat.

Cancel the polling request when the component unmounts. Never run automatic posting retries in a loop.

Browser download helper

async function downloadCscsReport(batchId, type, format) {
  const response = await api.get(
    `/api/cscs/uploads/${batchId}/export`,
    { params: { type, format }, responseType: 'blob' }
  );

  const disposition = response.headers['content-disposition'] || '';
  const match = disposition.match(/filename="?([^";]+)"?/i);
  const filename = match?.[1] || `cscs_${batchId}_${type}.${format}`;
  const url = URL.createObjectURL(response.data);
  const link = document.createElement('a');
  link.href = url;
  link.download = filename;
  link.click();
  URL.revokeObjectURL(url);
}
Authorization: report downloads require cscs.export. Do not attempt to open the URL in an unauthenticated browser tab if authentication is provided only through a bearer header.

12. Error handling contract

StatusMeaningRequired UI behavior
401Token missing or expiredEnd the session or refresh authentication.
403Permission or maker-checker separation failureDisable the action and display the API message.
404Batch, row, account, transaction or file not foundClear stale selection or return to the batch list.
422Validation/state/reconciliation/readiness failureShow validation errors and refresh current batch state.
429Rate limit exceededPrevent repeated clicks and retry after a delay.
500Sanitized technical failureShow the safe message/reference; do not expose raw stack data.

Laravel validation example

{
  "message": "The reason field is required.",

    "reason": ["The reason field is required."]
  }
}

Use a shared error helper that checks response.data.errors, then response.data.message, and finally a generic fallback.

13. Implementation checklist

  1. Use the numeric batch ID returned by the upload/import response.
  2. Load batch, preview and transactions in parallel.
  3. Use server pagination and meta.transaction_counts.
  4. Use meta.exception_counts for exception cards and tabs.
  5. Use decimal strings and register precision for quantities.
  6. Render buttons from allowed_actions plus frontend permissions.
  7. Refresh relevant reads after every successful mutation.
  8. Complete shareholder creation → account creation → CSCS mapping as one UI sequence.
  9. Reconcile before allowing submission.
  10. Keep approval and posting as distinct steps and messages.
  11. Call posting readiness immediately before displaying/confirming posting.
  12. Poll posting status only while queued or posting; cancel on unmount.
  13. Show verified success only from verification summary.
  14. Download reports as authenticated blobs.
  15. Test 403, 404, 422, 429 and stale-snapshot behavior.
